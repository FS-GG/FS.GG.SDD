# Provisional Work-Model Source Bundle Contract

**Status:** source-only FSC-04 prerequisite, stacked on draft #1009. **Owner:** FS.GG.SDD.

## Outcome

A pure verifier binds a producer-selected work-model source list to separately captured physical bytes and candidate source digests. It refuses an omitted source, an extra captured or candidate source, a case alias, path escape, stale selected text or raw bytes, and a wrong digest before returning any captured set. It has no output or publication capability.

## Requirements

- FR-001: The caller supplies `ViewGeneration.workModelSnapshots` selection independently of candidate rows. Version 2 and the work ID are exact. This verifier does not infer source authority from the candidate.
- FR-002: The provisional allowed source profile contains `.fsgg/{project,sdd,agents}.yml`, available authored `work/<id>/{spec,clarifications,checklist,plan,tasks,evidence}` files, and repository-relative performance paths declared by the captured physical `evidence.yml`. The three config paths and `spec.md` are required. A selected performance path requires selected evidence. `charter.md`, unbound performance paths, aliases, and escaping paths refuse.
- FR-003: Selected, captured, and candidate paths each have an exact set match with ordinal case-alias refusal. Captured digests must attest to exact raw bytes. A selected raw-byte field, when supplied, must match those bytes.
- FR-004: Decode captured bytes through the same strict `SkillMirror.decodeBody` used by the current command read edge. Compare decoded text to the selected text after applying the producer's evidence `sourceSnapshots` projection. Compare candidate digests to `SchemaVersion.sha256Text` of that selected text, including its CRLF normalization.
- FR-005: The verifier remains pure and read-only. It cannot write or authorize a generated view.
- FR-006: The physical evidence bytes must parse without diagnostics and match the selected work ID. Every declared performance artifact must be in the selected source set, even if the current producer would omit it after a missing or failed read. This stricter omission rule is a provisional fail-closed contract, not current production parity.
- FR-007: A Linux-only selected-file reader may capture one explicitly selected repository-relative performance path without declaring its unrelated siblings. It must traverse ancestors through pinned no-follow directory handles, refuse a linked or nonregular selected file, reject observed case aliases and parent roster mutation, and compare two reads plus supported metadata on the opened file descriptor. Its exact raw bytes and digest must bind to the v2 bundle; it must not write an output.

## Characterization and boundary

A disposable red-before fixture shows the v1 one-root contract accepting all three `.fsgg` sources while `work/<id>/spec.md` differs. This is a misuse of the v1 contract, not a defect in its one-root promise. The v2 bundle comparison requires the work path and declared performance sources in the same selected set. Independent tests cover missing and extra physical sources, candidate omission and case alias, wrong selected text and raw bytes, stale and malformed digests, unprojected evidence, disallowed charter, unsafe paths, work ID/version mismatch, and missing evidence for performance selection.

Default-branch `ViewGeneration.performanceEvidenceSnapshots` reads `budget.ArtifactPath` without restricting it to `readiness/<id>`, while the evidence cited-path rule accepts any contained repository-relative path. A direct producer test selects `tests/performance.txt`. Before this correction, the provisional comparator refused that valid selection and accepted a bundle that omitted a declared performance artifact from both candidate and captured lists. The corrected comparator derives the allowed path set from captured evidence and refuses that omission. It also refuses malformed physical evidence and selected performance paths absent from the declaration.

This pure join does not prove that the caller selected every producer source or that a supplied capture covers every physical entry in each root. Each single-root capture must independently establish its own closed set; a producer-owned coordinator must define how arbitrary contained performance paths are captured without admitting unrelated files. The current producer omits an artifact when its read is absent or failed; the provisional verifier instead refuses a declared omission, so adoption needs an explicit producer integration of the decision below. Separate captures are not an atomic cross-root snapshot. ABA, timestamp-hidden writes, mutations after the final check, Windows concurrency, package and installed parity, output rollback, publication, receiver pinning, and the GS2-10 candidate freeze remain separate acceptance boundaries.

## Absent and unreadable performance disposition

The provisional v2 source contract chooses **fail-closed** for both states. A declared performance artifact with no selected snapshot cannot authorize a complete work-model source bundle, whether the producer saw `ReadResult.Absent` or `ReadResult.Unreadable`. The comparator reports `MissingPerformanceSelection` in either case; an eventual command adapter may retain the distinct read reason for the operator. This is consistent with accepted feature 115 FR-009, which requires missing performance evidence to fail closed, and with the current evidence evaluator's `PerformanceMalformed` result for an absent artifact. It does not change the live generated-view path.

The current `workModelSnapshots` selector projects both read states through `snapshot` to `None` and omits the declared source. Two independent disposable red-before assertions requiring the path in that selection failed, one for `Absent` and one for `Unreadable`. The checked-in tests now document those omissions and show the v2 comparator refusing both, while an observed read passes. Producer adoption must surface the refusal before any output write; until that integration is reviewed, this draft is non-authorizing and does not claim current generation parity.

## Arbitrary performance parent closure

A declared `tests/performance.txt` is a valid producer-selected path, but its parent can contain unrelated files. The existing one-root physical adapter refuses `capture("tests", ["tests/performance.txt"])` when `tests/unrelated.txt` exists. Adding that sibling to the declared root set makes physical capture succeed but the v2 bundle rejects it as an unexpected source. An unselected symlink also refuses the root capture; a case alias to the selected name refuses as a duplicate. These are fail-closed observations, not permission to weaken the closed-root adapter.

The Linux `captureSelectedFile` adapter now treats a performance artifact as an explicitly selected file rather than asserting that its arbitrary parent is a closed producer root. It pins each ancestor with no-follow `openat`, inspects the selected name within held parent rosters, opens the selected regular file through that parent, and compares two byte passes plus supported inode/size/mtime/ctime fields from the opened descriptor. Observed path swaps, aliases, parent roster changes, linked ancestors, linked or nonregular leaves, and in-place writes refuse. Unrelated regular or linked siblings are ignored because they are not selected producer sources. A disposable integration control binds the resulting exact bytes to the pure bundle verifier while such siblings exist.

This per-file reader does not prove a simultaneous tree or cross-root snapshot. ABA, timestamp-hidden changes, mutation after the final check, and races outside the observed windows remain. It is Linux-only; Windows selected-file concurrency is unqualified. The producer still must select all sources independently, join the absent/unreadable refusal before any output effect, and establish capture ordering across roots. No installed parity, output rollback, publication, or receiver pin is claimed.
