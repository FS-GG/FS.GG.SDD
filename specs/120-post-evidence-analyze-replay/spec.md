# Feature Specification: Convergent Post-Evidence Analyze Replay

**Feature Branch**: `item/857-post-evidence-analyze-replay`  
**Created**: 2026-08-11  
**Status**: Draft  
**Input**: FS.GG.SDD#857

## Overview

A ship-ready work package must converge when the documented lifecycle replay is
run again. `evidence.yml` records the analysis it observed, while verify and ship
generate a work model enriched by that evidence. The source snapshot payload is
provenance, not an evidence declaration; hashing it back into the work model made
the analysis/model/evidence relationship self-referential.

## Requirements

- **FR-001**: `analyze` MUST use the existing evidence artifact as a work-model
  source when evidence exists, while still operating without it as the mandatory
  pre-implementation readiness gate.
- **FR-002**: Work-model source identity for evidence MUST exclude only the
  tool-owned `sourceSnapshots` payload. It MUST retain `sourceAnalysis`, all
  author-declared evidence, and all other evidence fields.
- **FR-003**: Evidence validation MUST continue to compare recorded source
  snapshots against the actual current sources and report stale evidence.
- **FR-004**: For a ship-ready package, two consecutive `analyze -> evidence ->
  verify -> ship -> refresh -> agents` replays MUST leave the second replay at
  `noChange` and preserve generated bytes.

## Acceptance Criteria

- **AC-001**: A pre-evidence analyze creates implementation readiness without
  requiring `evidence.yml`.
- **AC-002**: A completed lifecycle's first replay reaches the stable
  evidence-enriched representation and its second replay is entirely `noChange`.
- **AC-003**: Changing an evidence source after its snapshot was recorded still
  produces the existing stale-evidence diagnostic.

## Out of Scope

- Changing evidence declaration semantics or removing `sourceAnalysis`.
- Weakening observed-run requirements or ship readiness.
- Treating a missing or malformed evidence artifact as current.
