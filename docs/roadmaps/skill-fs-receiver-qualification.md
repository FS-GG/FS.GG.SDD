## Clean creation

The public qualifier installs `FS.GG.SDD.Cli` 2.0.3 and `FS.GG.Coord.Cli` 0.94.0 anonymously
from nuget.org. It scaffolds a clean console workspace through public
`FS.GG.Workspace.Template` 0.15.0, then proves:

- the tool manifest pins Coord.Cli 0.94.0;
- the visible `.agents` and `.claude` `work-roadmap` trees are byte-identical;
- none of the four retired Python helper names exists in either tree or the delivered workspace
  helper set;
- the driver invokes `fsgg-coord-engine skill roadmap-telemetry`; and
- installed configuration discovery returns the contracted `not-configured` result without state
  writes or credential loading.

Templates 0.15.0 supplies only the product template in this proof. The SDD 2.0.3 package supplies
the updated Drivers bytes and Coord.Cli pin; the qualifier therefore does not treat the Templates
release as evidence of SDD adoption.

## Retained upgrade and state

The supported retained procedure is digest guarded and resumable:

1. Read the existing scaffold provenance and verify every present `driverPaths` file against its
   recorded SHA-256. Refuse if any package-owned file was edited.
2. Remove only those verified package-owned files. Missing files are accepted, so an interruption
   can resume without widening the deletion set.
3. Update only the two owned entries in `.config/dotnet-tools.json` to SDD 2.0.3 and Coord.Cli
   0.94.0, retaining unrelated tool entries.
4. Run public `fsgg-sdd upgrade --root <workspace> --yes`. Its existing provenance-aware
   `artifactReSeed` step restores and records the current Drivers closure.

The qualifier scaffolds the retained input with public SDD 2.0.2, stops after half the guarded
retirement, resumes, and proves the second retirement pass is idempotent. It then proves an
owner-authored sentinel and a co-tenant tool entry remain byte-preserved, and that the upgraded
work-roadmap body equals clean creation.

Separately, it gives installed Coord.Cli 0.94.0 a retained schema-v1 Python-created
`begin-pending` state. A fake receiver accepts the submission, and the qualifier compares the
published bytes with the exact retained batch. The token and batch must survive unchanged. This
binds workspace upgrade to state compatibility without a live telemetry submission.
