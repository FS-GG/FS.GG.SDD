# FS.GG.SDD 0.26.0 migration

This release carries `FS.GG.Contracts` **6.0.0**. Its
`GovernanceHandoffSchema` record constructor now requires the typed
`PerformanceEvidence` list; see [the Contracts 6.0.0 declaration](../contracts-6.0.0.md).

Active `evidence[].performanceBudget` declarations now require an independently verifiable JSON
artifact with `contractVersion: performance-evidence-v1`. The summary-only text accepted by
0.24.x/0.25.x is malformed because its producer-authored p95/p99/catch-up values cannot be
recomputed.

For each run, emit a `sampleSets[]` entry containing raw `durationSamplesMs` and `catchUpFrames`
plus workload id/digest and class, target and thresholds, warmup/sample policy, host profile,
package versions, measurement scope/mode/capabilities, capture time/currency token, and
`probeReadbackContaminated`. SDD uses nearest-rank percentiles and maximum catch-up, and rejects
sets whose bindings differ before combining them.

A declaration with `liveCompositorRequired: true` must use `measurementMode: live-compositor` and
must not be probe/readback contaminated. Headless evidence remains valid for declarations that do
not require a live compositor.

Governance-handoff contract 1.2.0 adds `performanceEvidence[]`, carrying the raw bound artifact and
SDD's recomputed measurements. Consumers should read these facts directly and must not treat the
producer's optional `claimedBudgetPassed` value as authoritative.
