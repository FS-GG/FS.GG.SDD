# Migration to `2.0.0`

## Summary

`2.0.0` makes Quint the default Typed SDD authority. A `typed-sdd author`
invocation that omits `--backend` now selects `quint-specification-v1`; through
`1.8.0`, the same invocation selected `fsharp-specification-v1`.

The new default is the single lifecycle described by the accepted workspace
model, exact-base proposals, explicit human acceptance, deterministic
reconciliation, and fingerprint-bound implementation correspondence. Explicit
F# authority remains supported for the 2.x compatibility window, and legacy
`none`, `sdd`, `typed-sdd`, and `spec-kit` workspaces remain inspectable and
migratable without token aliasing.

## Breaking change and adaptation

| Breaking change | Affected contract | Adaptation |
|---|---|---|
| Omitting `--backend` selects `quint-specification-v1` instead of `fsharp-specification-v1`. | `fsgg-sdd typed-sdd author` default behavior and generated authority format | Provision the pinned Quint/lmt objects and accept the new default, or pass `--backend fsharp-specification-v1` to preserve the former format during migration. |

To keep the earlier behavior explicitly:

```sh
fsgg-sdd typed-sdd author \
  --root . \
  --work example \
  --agent "$USER" \
  --session migration \
  --backend fsharp-specification-v1
```

To adopt the 2.0 default, first provision the exact supported tool objects as
described in [Typed SDD tool provisioning](../../reference/typed-sdd-provisioning.md),
then omit `--backend` or pass `--backend quint-specification-v1` explicitly.

The migration planner is dry-run-first and preserves original byte identities
and rollback evidence. Preview an existing workspace before applying any
effectful migration.
