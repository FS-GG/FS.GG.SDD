# FS.GG.SDD 0.27.0 migration

Interactive and render-loop projects now declare `project.profile` and a typed
`performanceIntent` in `spec.md` front matter before `analyze` can report
`implementationReady`.

Active intent requires target FPS, normal workload ids and definition digests, expected maximum
scale, timing thresholds, structural cost ceilings, required measurement capability, and
live-compositor posture. Later `evidence[].performanceBudget.intent` must equal that declaration.

Use `disposition: not-applicable` only with a rationale and evidence references. A
`disposition: deferred` declaration must name performance debt and remains blocking.
Non-interactive projects and legacy evidence keep their previous behavior.

This release carries `FS.GG.Contracts` 7.0.0 and governance-handoff contract 2.0.0.
