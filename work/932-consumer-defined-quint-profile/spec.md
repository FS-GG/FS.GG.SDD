# General Consumer-Defined Quint Model Profile Specification

Prose status: specified

## User Value
Package consumers can make a complete bounded Quint model their reviewer-facing authority and compile its declared facts and behavior into deterministic contracts and native/Fable-compatible bindings without being limited to the three frozen Q1 examples.

## Scope
- SB-001: Add a versioned general consumer-defined profile beside frozen profile 1 for bounded models containing declared catalogue facts, pure functions, external-algorithm registrations, state, actions, invariants, and executable runs.
- SB-002: Project a closed language-neutral value and relationship vocabulary from the model into deterministic compiled contracts and generated native/Fable bindings.
- SB-003: Dispatch the existing hermetic Typed SDD host by explicit profile identity and preserve exact tool, source, extraction, type/effect, contract, binding, and receipt identities.
- SB-004: Qualify the profile with the complete 16-rule S.I.R. combat authority and publish the Artifacts/CLI changes as one coherent stable set.

## Non-Goals
- SB-005: Do not change, generalize, or regenerate `fsgg-quint-profile/1` or its three admitted typed-effect digests.
- SB-006: Do not expose raw Quint IR, compiler node ids, or arbitrary executable expressions in the public compiled contract.
- SB-007: Do not implement registered external algorithms, infer domain semantics, download tools, accept moving versions, or require Governance at runtime.
- SB-008: Do not make unbounded model checking a publication prerequisite; verification depth remains an explicit, bounded consumer contract.

## User Stories
- US-001 (P1): As a package consumer, I can compile my own bounded literate Quint model without asking FS.GG.SDD to hard-code its module digest.
- US-002 (P1): As a consumer developer, I can use deterministic generated native/Fable bindings for every declared model catalogue value and stable semantic identity.
- US-003 (P1): As a compatibility owner, I can upgrade without changing any profile-1 authority, contract, binding, receipt, diagnostic, or lifecycle behavior.
- US-004 (P1): As a release reviewer, I can reproduce the compilation from installed packages and prove that substituted profiles, stale outputs, unsupported effects, and runtime divergences fail closed.
- US-005 (P2): As a formal-modeling learner, I can inspect one real model that demonstrates Quint at catalogue, formula, external-contract, transition, invariant, and scenario granularity.

## Acceptance Scenarios
- AC-001 [US-001] [FR-001] [FR-002]: Given an exact toolchain and a bounded consumer model not present in the profile-1 digest table, when compilation selects the general profile twice in isolated roots, then both runs accept and every contract, binding, and receipt byte agrees.
- AC-002 [US-002] [FR-003] [FR-004]: Given the complete S.I.R. combat authority, when compilation projects its declared catalogue and relationships, then all 16 rule identities and their metadata are present exactly once and the native and Fable binding sources are byte-identical.
- AC-003 [US-001] [US-004] [FR-005] [FR-006]: Given unsupported typed/effect structure, unbound semantic rows, duplicate identities, unsafe values, profile substitution, or stale generated output, when compilation or validation runs, then it refuses with deterministic source-located diagnostics and writes no accepted authority.
- AC-004 [US-003] [FR-007]: Given every existing profile-1 golden fixture and lifecycle route, when the coherent set is upgraded, then all prior public APIs, canonical bytes, diagnostics, and tests remain unchanged.
- AC-005 [US-004] [FR-008] [FR-009]: Given only installed packages, a preseeded exact cache, poisoned network access, and the S.I.R. consumer fixture, when the full authority lifecycle and runtime replay run, then compilation is hermetic, the bindings compile natively and through Fable, and every declared mutation turns the gate red.
- AC-006 [US-005] [FR-010]: Given the published guidance and S.I.R. authority, when a reviewer follows the documented walkthrough, then each supported modeling granularity, its boundedness decision, and the boundary between model semantics and registered implementation is explicit and reproducible.

## Functional Requirements
- FR-001: The system MUST add one explicit general consumer-defined profile identity while retaining the existing profile identity as a distinct frozen choice; file contents or module names MUST NOT infer the profile. (Stories: US-001, US-003; Acceptance: AC-001, AC-004)
- FR-002: The general profile MUST accept bounded consumer modules independent of an allow-listed whole-program digest while still validating the exact Quint version, closed typed/effect shape, declared root module, source bindings, stable identities, and resource ceilings. (Stories: US-001, US-004; Acceptance: AC-001, AC-003)
- FR-003: All semantic catalogue data required by generated consumers MUST originate in the literate Quint authority and MUST project through a closed deterministic vocabulary supporting the S.I.R. catalogue without a semantic sidecar. (Stories: US-001, US-002; Acceptance: AC-002)
- FR-004: The compiled contract and generated native/Fable bindings MUST preserve stable identities, catalogue values, action reads/writes/subjects, relationships, verification declarations, finite bounds, impacts, compatibility facts, and semantic digests in ordinal deterministic order. (Stories: US-002; Acceptance: AC-002)
- FR-005: Profile validation MUST reject duplicate or colliding identities, unknown fields or effects, unbound rows, unsafe paths/ranges, non-canonical values, resource-limit excess, and any raw compiler identity or executable expression that could escape into the public contract. (Stories: US-004; Acceptance: AC-003)
- FR-006: Profile selection, extraction, typecheck adaptation, contract compilation, binding generation, receipts, and Typed SDD author/inspect/migrate/rollback dispatch MUST bind the same explicit profile identity and fail atomically on substitution or stale products. (Stories: US-001, US-004; Acceptance: AC-003)
- FR-007: Existing profile-1 APIs, accepted typed-effect digests, compiled-contract v1 bytes, generated bindings, diagnostics, fixtures, lifecycle commands, and manifest-v2 authorities MUST remain byte- and behavior-compatible. (Stories: US-003; Acceptance: AC-004)
- FR-008: Package-only acceptance MUST use exact stable Artifacts/CLI packages, fresh caches, a preseeded content-addressed toolchain, poisoned network access, no source/project checkout edge, and two isolated compilations of the complete S.I.R. authority. (Stories: US-004; Acceptance: AC-005)
- FR-009: Qualification MUST prove named Quint witnesses, bounded seeded simulations, native and Fable binding compilation, sampled production-interpreter correspondence, and independent profile, freshness, semantic, mapping, observable, and interpreter mutation controls. (Stories: US-004; Acceptance: AC-005)
- FR-010: Public signatures, API-surface baselines, lifecycle/reference/release documentation, and equivalent packaged author/migrate skills MUST teach the profile contract, supported model/value boundaries, bounded verification choices, and registered-external-algorithm seam. (Stories: US-005; Acceptance: AC-006)
